### d7d4264
1. **Double speed after turning split screen off mid-battle.** The Draw hook in
   `src/local_versus.cpp` only reset `guest_vblank_multiplier` to 1 while
   `split_screen` was still on. Unticking it during a battle left it at 2 until
   restart. Now a static `multiplier_set` remembers whether the hook raised it,
   and puts it back whenever it had.
2. **Unchecked final flush when unpacking the package.** `CopyEntry` in
   `src/game_files.cpp` never checked the `ofstream`'s final flush. A full disk
   could leave a truncated `default.xex`, which is written last to mark a
   finished unpack. Now it calls `out.close()` and checks `fail()`.
3. **`--watch_u32` typo crashed the game.** `std::stoul` threw inside the
   present hook. Bad entries are now caught, logged and skipped.

### 2817ea9 (needs the SDK rebuilt)
4. **Split-screen halves could swap permanently.** Before, `TagSwap()` pushed a
   view tag at the *start* of the present function `sub_822D3180`. The D3D12
   `IssueSwap` pops one tag per swap. If a present returned without calling
   VdSwap, one extra tag stayed queued and every later frame landed on the wrong
   side. Now:
   - SDK API (`rex/system/split_screen.h`): `PushSwapTag` has been replaced by
     `SetNextSwapView(view)`, which is called by the title, and `OnGuestSwap()`,
     which is called by `VdSwap_entry` in `src/kernel/xboxkrnl/xboxkrnl_video.cpp`
     right before it writes the swap packet. It queues the pending view and
     resets it to `kNoView`.
   - `TagSwap()` now calls `SetNextSwapView`. If a present is skipped, the next
     call just overwrites the pending view, so the queue can't drift.
   - Checked in SDK source: VdSwap writes one non-predicated `PM4_XE_SWAP`, and
     `ExecutePacketType3_XE_SWAP` calls `IssueSwap` once, so it's 1:1.
5. **Second per-view Draw call only got `r3` back.** The split-screen loop in
   the `sub_82123758` hook now snapshots the whole `PPCContext` and restores it
   before each view. If Draw takes arguments in r4–r10 or f1–f13, the second call
   used to get clobbered values. Callee-saved registers come back unchanged
   anyway, so this is the same as calling it twice with the same inputs.

## Build steps

1. **Rebuild the patched SDK.** Commit `2817ea9` changes `0002-split-screen.patch`.
   An SDK built from the old patch fails to link with an undefined
   `rex::system::split_screen::SetNextSwapView`. That error is expected and means
   the SDK is stale.
   ```
   cd <rexglue-sdk checkout>        # build.bat looks for ..\tools\rexsdk-custom as the install prefix
   git checkout -- . && git clean -fd
   git checkout v0.10.0
   git apply <Oratan-recomp>/sdk-patches/0001-present-vsync.patch
   git apply <Oratan-recomp>/sdk-patches/0002-split-screen.patch
   cmake --preset win-amd64 -DCMAKE_INSTALL_PREFIX=<prefix>
   cmake --build out/build/win-amd64 --config Release --target install
   ```
   Both patches were checked with `git apply --check` against a clean v0.10.0
   checkout (Linux). If `git apply` complains about line endings on Windows, make
   sure the patch files weren't converted to CRLF (`.gitattributes` has
   `*.patch -text`).
2. **Build the game:** `build.bat` (or the cmake commands in README.md).
3. **Copy the new runtime DLLs** next to `oratan.exe` if your setup doesn't
   already do that (`rexruntime.dll` and `rexgpu-xenos.dll` must come from the
   patched SDK).

Possible compile issues to watch for (I couldn't compile):

  `include/rex/ppc/context.h` (v0.10.0), so it should be.
- `src/debug_tools.cpp` now includes `<exception>` and catches

## Performance notes

- Split screen renders two full 1280×720×scale frames per tick, plus two extra
  full-texture copies and an extra submission. The result is letterboxed at
  half size. At 3–4× resolution that is very expensive. Options: cap the scale
  while split, or render with an 8:9 projection.
- The release build has no `-march`. x86-64-v3 might help the recompiled vector
  code, but costs compatibility with CPUs older than about 2013. Benchmark it
  before deciding.

## Online multiplayer (summary of the feasibility report)

SDK v0.10.0 networking is stock Xenia stubs:
- `XNetGetTitleXnAddr` returns loopback.
- `XNetXnAddrToInAddr` always fails.
- All XSession calls just log and return success.
- `signin_state()` is hardcoded to 1, meaning signed in locally, never Live.

The game's NETVS mode (module 2) can't connect.

- **A. Emulate Live / System Link in the SDK.** This would make the original
  NETVS mode work. System Link: weeks. Live-style matchmaking: months.
- **B. Lockstep input netplay on top of local versus.** Recommended first. Uses
  the input records at `0x829BEFA8` (stride 316, pad index at +300), the
  `sub_822A71B0` hook and `view_camera`:
  - Exchange inputs each frame.
  - Do a pre-match handshake (character, stage, random seed).
  - Hash the battle state each frame for desync detection.
  - Effort: a few weeks.
- **C. Rollback.** Needs B proven deterministic, plus a cheap battle-state
  save/restore and the game's Update function (not yet identified). Effort:
  months.
